# Настройка подключения

## Переменные среды

Клиент читает только окружение текущего процесса:

| Переменная | Значение |
| --- | --- |
| `OKDESK_SITE_URL` | `https://<account>.okdesk.ru` без дополнительного пути, query и реквизитов |
| `OKDESK_API_TOKEN` | API-ключ сотрудника с необходимыми правами чтения |

Ключ создаётся в разделе API настроек своего аккаунта Okdesk. Клиент не создаёт ключи и не использует логин/пароль. Наличие ключа не заменяет права сотрудника на конкретную заявку, оборудование или файл.

Следующие блоки предназначены для ручного выполнения в своём PowerShell. Они записывают пользовательские переменные Windows. Агент не запускает эти блоки автоматически.

Адрес:

```powershell
[Environment]::SetEnvironmentVariable(
    'OKDESK_SITE_URL',
    (Read-Host 'URL аккаунта Okdesk').Trim().TrimEnd('/'),
    'User'
)
```

API-ключ со скрытым вводом:

```powershell
$okdeskToken = Read-Host 'API-ключ сотрудника Okdesk' -AsSecureString
try {
    [Environment]::SetEnvironmentVariable(
        'OKDESK_API_TOKEN',
        [System.Net.NetworkCredential]::new('', $okdeskToken).Password,
        'User'
    )
}
finally {
    $okdeskToken.Dispose()
    Remove-Variable okdeskToken
}
```

Самого ключа нет в тексте команды, истории введённых команд и выводе скрытого ввода. Пользовательская переменная среды Windows при этом хранит обычную строку, а не зашифрованный SecureString: доступные этому пользователю процессы могут прочитать её. Это тот же способ настройки, что у Jira-клиента; называть такое хранение зашифрованным нельзя. Не присылать ключ в чат и не записывать его в `.env` или файлы проекта.

Полностью перезапустить Codex после настройки. Открытый ранее процесс и его терминалы могут сохранять старое окружение. Не выводить значение токена и полный дамп окружения для проверки.

## Первое чтение

После настройки выбрать реальную заявку и разрешить конкретную команду. Например, для вымышленной заявки 12345:

```powershell
pwsh -NoProfile -File 'D:\Media\User\source\repos\work\codex-okdesk-workflow\client\okdesk.ps1' -Command GetIssue -IssueId 12345 -WithAttachments
```

Команда делает реальные GET-запросы. Она сохраняет данные локально, но ничего не изменяет в Okdesk. Для обычного полного разбора использовать `-WithAttachments`; без него получаются тексты, оборудование и список файлов без скачивания. После запуска прочитать `textPath`, при необходимости `snapshotPath`, обязательно `manifestPath`; изображения открыть доступным инструментом просмотра.

## Дополнительные домены файлов

Сайт аккаунта, `static.okdesk.ru`, `static.okdesk.com` и `okdesk.storage.yandexcloud.net` разрешены для скачивания по умолчанию. Если изображения обслуживаются через собственный домен, после явного подтверждения его владельца передать точное DNS-имя в `-TrustedFileHosts`:

```powershell
pwsh -NoProfile -File '<clientRepositoryPath>\client\okdesk.ps1' -Command GetIssue -IssueId 12345 -WithAttachments -TrustedFileHosts files.example.org
```

Параметр действует только на этот запуск и также доступен у `DownloadAttachments`. Для нескольких доменов использовать массив при вызове из PowerShell через `&`, как и для `AttachmentIds`. URL, IP-адреса, порты и маски не принимаются. API-ключ на дополнительные домены не передаётся; перенаправления проходят те же проверки. Не добавлять домен только на основании его появления в описании заявки.

Ошибка проверки сообщает, отклонён исходный адрес или перенаправление, и конкретную причину. Для недоверенного хоста показывается только его имя; временная ссылка, query и ключ не выводятся. Такая ошибка возникает в локальном клиенте и сама по себе не указывает на недостаточные права API-ключа.

## Подключение скилла отдельно

В этом проекте находится распространяемая копия `skills/okdesk-workflow`; создание проекта не устанавливает её в Codex. Установку выполнять только по отдельной просьбе.

При установке выбрать фактически используемый каталог личных скиллов в данной среде. В среде с существующей установкой Jira в `%USERPROFILE%\.codex\skills` можно использовать соседнюю папку `okdesk-workflow`; не создавать дубликат с тем же именем в другом каталоге. Копировать всю папку скилла. Если новый скилл не появился, перезапустить Codex.

Путь клиента не зашит в распространяемый скилл. При первом обращении указать абсолютную папку проекта. После подтверждения пути установленная копия может сохранить `references/local-client.json`:

```json
{
  "clientRepositoryPath": "D:/Media/User/source/repos/work/codex-okdesk-workflow"
}
```

Этот персональный файл не входит в распространяемую копию. Не создавать его при подготовке проекта без установки скилла.

Если дополнительные домены уже подтверждены человеком, установленная копия может сохранить их в необязательном массиве `trustedFileHosts` этого же файла и передавать в `-TrustedFileHosts` при скачивании. Сам клиент этот файл не читает. Сохранять подтверждённые имена отдельно от общих инструкций скилла; не переносить их в распространяемую копию.

## Обновление и перенос

Обновлять `client/` и распространяемый скилл совместно. Если отдельно поручено обновить установленный скилл, синхронизировать его `SKILL.md`, `agents/openai.yaml` и `references/client-usage.md`, сохранив персональный `references/local-client.json`. Перед заменой сравнить обе копии и сохранить независимые изменения. Не устанавливать скилл только потому, что он обновился в проекте.

При переносе клиента указать новый абсолютный путь в установленном скилле после подтверждения. Переменные среды и содержимое `data/` автоматически не менять.
