# Устройство и эксплуатация

Клиент разделён на точку входа, HTTP-модуль, локальное хранение и сбор контекста. Настройка подключения — в [setup.md](setup.md), правила обращения с секретами — в [security.md](security.md). Правила поведения агента находятся в [скилле](../../skills/okdesk-workflow/SKILL.md).

## Команды

| Команда | Обязательные параметры | Результат |
| --- | --- | --- |
| `GetIssue` | `-IssueId` | Заявка, комментарии, всё непосредственно прикреплённое оборудование, текст/JSON |
| `GetIssue -WithAttachments` | `-IssueId` | Дополнительно файлы заявки и комментариев, встроенные изображения, манифест |
| `DownloadAttachments` | `-IssueId` | Файлы заявки и комментариев; оборудование повторно не читается |
| `GetEquipment` | `-EquipmentId` | Полная возвращённая карточка оборудования, текст/JSON |
| `GetEquipmentParameters` | Нет | Схема доступных дополнительных атрибутов оборудования |

Для команд скачивания необязательны `-AttachmentIds` (список выбранных ID) и `-ApprovedLargeAttachmentIds` (согласованные файлы больше 500 000 000 байт). Если выбран конкретный набор, разрешение на большой файл должно относиться к этому набору. Внешние URL и произвольный HTTP-метод в командную строку передать нельзя.

## API

Используются только:

```text
GET /api/v1/issues/{id}
GET /api/v1/issues/{id}/comments
GET /api/v1/issues/{id}/attachments/{attachment_id}
GET /api/v1/equipments/{id}
GET /api/v1/equipments/parameters
```

Ключ передаётся в query `api_token`, как требует API Okdesk. Запросы с ключом допускаются только к настроенному HTTPS-сайту аккаунта; перенаправления API не выполняются. GET-комментарии возвращаются массивом; документация этого метода не задаёт пагинацию. Клиент проверяет ID комментариев и сверяет количество с карточкой заявки. При несовпадении прекращает сбор, поскольку данные могли измениться или оказаться ограниченными по правам. Не добавлять вымышленные параметры пагинации.

Список вложений объединяется из карточки заявки и всех комментариев по ID. Ссылка на файл запрашивается непосредственно перед скачиванием: по документации она действует 30 секунд. Файл читается потоком, проверяются длина и SHA-256. Автоматического повтора запросов нет; после ошибки следующее чтение получает свежую ссылку.

Скачивание выполняет отдельный HTTP-клиент без ключа, cookies и заголовка авторизации. Разрешены HTTPS-хост аккаунта и `static.okdesk.ru`, включая проверку каждого перенаправления. Другой CDN или пользовательский домен требует адресного изменения списка доверенных хостов после проверки; передавать ему ключ нельзя.

## Изображения и оборудование

Обычные картинки скачиваются вместе с остальными вложениями. Дополнительно разбираются `img src` в описании и комментариях, data URI распространённых растровых форматов и PNG base64 в параметрах заявки/оборудования. HTML не исполняется. Внешние картинки с других хостов, `srcset` без `src`, неподдерживаемые data URI и недоступные изображения отражаются как `unavailable`; агент должен назвать ограничение. Скачивание файла само по себе не подтверждает, что агент его просмотрел.

Версия iiko не является заранее известным системным полем Okdesk: агент читает реальные `parameters` с `code`, `name`, `field_type`, `value`. Клиент сохраняет все возвращённые поля оборудования. `parent_id` также сохраняется; родительские карточки автоматически не обходятся. По необходимости агент может отдельно прочитать конкретного родителя через `GetEquipment`. Поиска по всей компании, файлам оборудования и объектам обслуживания в этой версии нет.

## Результаты и хранение

Успешный stdout — один JSON с `ok`, `command`, `cleanedRuns`, `data`. Полезные поля `data`: `textPath`, `snapshotPath`, `manifestPath`, количество комментариев/оборудования/вложений, `downloads`, `images`, `reviewRequired`. Последнее поле означает пропущенные большие файлы или недоступные встроенные изображения. `attachmentsRequested=false` явно обозначает сбор без скачивания. При ошибке JSON идёт в stderr, код завершения — 1; `partialDataPath`, если присутствует, содержит неполный результат.

Каждый запуск создаёт уникальную папку `data/<SHA-256 сайта и ключа>/runs/<UUID>/`. Смена ключа создаёт отдельное пространство данных и не переиспользует материалы, прочитанные с другими правами. Повторное чтение всегда получает свежие данные; кэш вложений не используется. Отпечаток разделяет локальное хранение, но не доказывает личность сотрудника.

Одновременные вызовы для одного пространства защищены эксклюзивной блокировкой; второй вызов завершается с понятной ошибкой. При обращении, не чаще одного раза в сутки, удаляются собственные результаты этого пространства старше 30 дней с момента сбора. Ручное открытие файлов срок не продлевает. При смене ключа старые пространства автоматически не очищаются. Удаление затрагивает только локальный `data/`; записи Okdesk не изменяются. Перед удалением проверяются маркер принадлежности, абсолютные границы и отсутствие reparse points во всём дереве.

## Проверка

Синтаксис `.ps1`/`.psm1` можно проверять штатным `System.Management.Automation.Language.Parser.ParseFile` без выполнения клиента. Запуск самого клиента или будущих тестов требует отдельного разрешения на точную команду. Тесты должны использовать подставной HTTP-транспорт и изолированный временный каталог, без настоящих ключей и запросов.

Интеграционная приёмка требует реального адреса аккаунта, настроенного локально ключа и заявки со скриншотом в комментарии и сервером в оборудовании. Проверить доступ к закрытым комментариям, список и содержимое вложений, значение версии iiko и отсутствие секрета в результатах. Разбор синтаксиса не подтверждает эти сценарии.
